# 3. 本番（A5・グレー600dpi）への組み方

> 先に読むもの：[docs/page-spec.md](../page-spec.md)（大きさ・安全域・右綴じ・見開き・書き出し）、README の `tools/studio.py`（plan → review → approve → cut → draw → pick → build → check → export）、[skills/03_lettering.md](../../skills/03_lettering.md)、[skills/04_checklist.md](../../skills/04_checklist.md)。
> この章は、その流れの**考え方と、うちで分かった注意**です。

## 3-1. 流れの考え方

```
Codex で1ページの設計図（ネーム・文字なし）
  → コマごとに高解像で描き直す（ローカル I2I／Codex でコマだけ）
  → 原寸で組む（3638×5102・塗り足し・見開き）
  → 写植（文字はフォントで焼く）
  → 白の掃除 → 検収 → 001.png…
```

- いちばん時間を守れるのは**全ページのネームを先にそろえる**こと（README）。
- 画像生成に文字を描かせない（毎日マンガは文字入りで描いていますが、本番は誤字を避けるため写植）。
- 🔴 **原寸でページを通して試し刷りで見た記録は、まだありません**（2026-11-20 時点）。ここに書く方法は、毎日マンガ（SNS 用・1024×1536）で確かめたことと調査からの案です。

## 3-2. 原寸の画質

- 半ページ大のコマは原寸で約3500×2500px。1MP（約1024×1024）で描いたものを**単純に引き伸ばさない**。dpi の表示だけを変えるのも不可（page-spec）。
- 高解像にする手の候補：
  - ローカルの hires（1.5倍で描き直す）＝832×1216 → 1248×1824、1枚 約95秒〔実測〕
  - Codex のコマを元にした I2I（[02](02_local_generation.md) 2-6）
  - どれで原寸の画質に届くかは**試験中**。A5 の実物印刷で見て決める予定
- `tools/studio.py plan` で、各コマの拡大率を描く前に見られます。

## 3-3. 白を真っ白にそろえる

AI で描いた絵は、白に見えるところも 235〜254 のノイズが全面に残っています（レベル補正を最大にすると見える）。印刷で薄いザラつき・点々になるおそれがあります。

- 測った値：白っぽい画素のうち真っ白（255）の割合＝Codex のマンガ 11%・設定画 19%・ローカル LoRA の絵 3%（吹き出しの中もノイズ）〔実測・2026-11-19〕
- 明るさ一定以上（目安 235）を 255 にそろえると 100% になり、線とトーンは残った〔実測〕。どこまで白くするか（しきい値）は試し刷りで決める。
- やり方の例（Pillow）：グレーに変換 → 235 以上の画素を 255 に → 真っ白の割合を測って確かめる。書き出しの前に全ページへ。

```python
from PIL import Image

THRESHOLD = 235  # 目安。試し刷りで決める
img = Image.open("001.png").convert("L")              # グレーに
img = img.point(lambda v: 255 if v >= THRESHOLD else v)  # 235 以上を 255 に
hist = img.histogram()
print(f"真っ白(255)の割合: {hist[255] / sum(hist):.1%}")
img.save("001_white.png")                             # 元の画像は残す
```

- きっかけ＝しのりさんの実験（https://x.com/shinori_to/status/2123005906992668941 ）〔他者の経験則〕
- この処理を `export` に組み込むのは次の版以降の予定。

## 3-4. トーン・ベタの注意（印刷）

〔調査（一次）・印刷所の案内。最終的には自分の印刷所の入稿仕様が正〕

- AI に `screentone` と頼んで出る点々は、**印刷用の正しい網点とは限らない**。網点の拡大縮小・異なる線数や角度の重ね・グレーとトーンの重ねはモアレの原因になる（緑陽社 https://www.ryokuyou.co.jp/doujin/column/moire2.html ）。
- 順番の案：**絵の最終寸法を決める → 線とグレーを整える → 必要なら管理できるトーンに置き換える → 書き出す**。トーンを付けたあとで縮小・拡大しない。
- グレースケール本文は 600ppi 推奨、グレーの描写がない原稿はモノクロ二階調（600 または 1200）（緑陽社）。オンデマンドは 60線程度・600dpi 推奨（ねこのしっぽ https://www.shippo.co.jp/neko/faq_1.shtml ）。
- オンデマンドでは広いベタ・平網にムラや白抜けが出ることがある（ホープツーワン https://hope21.jp/creative-guide/aboutondemand/ ）。黒の多いバトル原稿は、紙と印刷方式の見本で判断。
- トーンの調整に使えそうな道具（未導入・案）：Krita（網点を解像度・線数で調整）、ImageMagick（二値化・網点化・形式変換を全ページで統一）〔調査（二次）〕。

## 3-5. 見開き・ノド

- 顔とセリフは綴じ側15mm（page-spec）に入れない。無線綴じではノドから10mm以上離す、という印刷所の目安もある（ねこのしっぽ）〔調査（一次）〕。
- 見開きは1枚絵より「ノドをまたぐ横長コマ2〜3個」のほうが扱いやすい（page-spec）。
- 見せ場は「縦いっぱい」か「見開き」に置き、そのページのコマは3コマ以下に（[01](01_codex_one_page.md) 1-2）。
- めくった先に答えを置く。見開きの決め顔・命中点をノドに置かない（作画教材からの応用案）〔調査（二次）：https://tips.clip-studio.com/ja-jp/articles/1752 〕。

## 3-6. バトルのページの組み立て（調べものから）

〔調査（二次）＋応用案。作家の方法であって、全バトル漫画の決まりではない〕

- 動作を1コマに詰めこまない（回避と反撃は別のコマ）。いちばん見せたい見開きのアクションから逆算して前のコマと面積を決める（https://www.clipstudio.net/oekaki/archives/151574 ）。
- 開戦時と移動後に「引き」を置いて、人物・遮蔽物・距離を見せる。
- 刃の軌道と当たる点を見せる。斬撃のエフェクトで武器を隠さない。
- 体・髪・服・流線の向きをそろえる。
- 静かなコマをはさむと、強い一撃との落差が出る。
- 1コマの頼み方の案（効き具合は未検証）：カメラ・左右の位置（`screen-right` は画面の右、`her left hand` は本人の左手）・その瞬間の動作1つ・当たる点・セリフを後で入れる空き場所、を書く。

## 3-7. 合同誌として

〔調査（一次）〕

- コミケの公式資料（C109 アピール・2026-11-06 公開）では、生成 AI 作品の一律禁止・AI 利用の申告義務は確認できなかった（2026-11-12 時点）。奥付には**サークル名・連絡先・発行日・印刷会社名**が必須（https://www.comiket.co.jp/info-c/C109/C109Appeal.pdf ）。個別の権利処理を保証するものではない。
- AIニケちゃんが出る作品は「非公式のファンメイド作品」＋キャラ名の表示が必須・印刷物は原価回収まで（公式ガイドライン・[docs/rights-and-characters.md](../rights-and-characters.md)）。`tools/studio.py check` がこの表示の有無を調べます。
- 合同誌では本文を見開きファイルのまま入稿せずページごとに・ノンブルは本全体で通す、という印刷所の指定がある（トム出版 https://www.tomshuppan.co.jp/topics/q_a.html ）。
- 作品名・作者名・開始ページが結びついていないと読者が作者を探しにくい、という読者の報告がある〔他者の経験則：https://hanbunningen.hatenablog.com/entry/2016/05/18/132507 〕。
